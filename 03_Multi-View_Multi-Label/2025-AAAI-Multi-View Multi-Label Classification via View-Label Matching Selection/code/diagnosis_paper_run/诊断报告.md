# VAMS 第二轮诊断（2026-10-01）

结论：发现上一轮公式对齐修改引入的**标签节点编号依赖**，已修复并通过回归核验。另发现 dropout 参数实际不生效和固定分批顺序；消息尺度与学习率是线索，未证明造成论文分数差距。本轮没有新增完整训练或测试指标。

## 1. 已确认并修复：有序拼接与任意节点编号混在一起

上一版本 `paper_graph.py` 用上三角选择一条无向边，以较小编号节点的属性在前拼接。`paper_gn.py` 又把这一个有序边状态给两端共用，但边更新器是普通 MLP，并不满足 `rho([a,b])=rho([b,a])`。

因此，只改变标签节点的存储编号，就会改变同一对真实标签在拼接中的左右位置。完全标签图虽然没有少边，模型仍不具有标签节点排列等变性。这与改变真实标签身份不同：诊断把身份向量随节点一起移动，并对输出作逆置换，不改任何模型权重。

使用保存的第 33 轮模型，仅对 95 行验证样本检查：

| 检查 | 最大概率变化 | 改变阈值分类的位置数 |
| --- | ---: | ---: |
| v3 倒序标签编号 | 0.671636 | 80 / 570 |
| v3 循环移动标签编号 | 0.712229 | 71 / 570 |
| 上一版 v2 倒序编号 | 0.00000161 | 0 |
| 上一版 v2 循环移动编号 | 0.00000152 | 0 |
| 修复后 v4，沿用 v3 权重，仅倒序编号 | 0.00000149 | 0 |
| 修复后 v4，沿用 v3 权重，仅循环移动编号 | 0.00000167 | 0 |

边模块局部检查也确认：只交换标签边的两个端点索引，保持旧边属性不变，第一层更新边属性最大变化为 4.5178。这说明原 MLP 对拼接顺序敏感；将同一份状态按任意编号赋给两端，不能保证编号无关。

该问题由上一轮修改引入。此前逐公式、梯度及重放检查遗漏了节点重排这一行为约束；那些检查通过不代表完整模型语义正确。

修复只针对这个问题：视图/标签的无向拓扑采用双向消息表示，各方向的边属性按 `[接收节点,发送节点]` 排列，每个节点只聚合发送给自己的消息。邻居消息固定中心为接收节点，拼接中心在前、邻居在后；视图—标签边仍按两种节点角色固定拼接。独立消息 MLP、两阶段边更新、层数、损失和学习率不变。版本标识改为 v4。

这是一种可验证的角色排序实现，不代表论文给出了唯一的无向边状态实现。此前把“无向”直接解释为“共用一份按编号排序的有序拼接边”过于武断。

`verify_label_order.py --require-invariant` 在 v3 上先失败；`--implementation workspace --require-invariant` 在修复后通过。随机模型的 CPU/GPU 检查也加入了节点身份不变的标签重排断言。

v4 检查见 `../formula_alignment_v4/verification_cpu.json`、`verification_cuda.json`；冻结源码见其 `source/` 和 `source_manifest.json`。旧 v3 源码、模型、分数保持原样。

**这些检查只证明编号依赖已修正。沿用旧权重做行为测试，不是重新训练后的 v4 成绩；不能把旧 LRAP 0.7843 当成 v4 分数，也不能量化此缺陷解释了多少论文差距。**

## 2. 已确认的训练接线问题：dropout 参数不生效

本次配置 `dropout=0.4`，但是模型内实际 `nn.Dropout` 模块数为 0。作者的 `MLP.py` 中 Dropout 调用全部被注释，参数仅保存为普通属性；图网络也没有 Dropout。

因此，“使用 dropout=0.4 训练”是不准确的。是否启用 Dropout 是另一个训练行为改动，不能因泛化分数不够就把它包装成论文确定要求，本轮没有启用。若后续启用，KNN 构建用 eval 状态而批次编码用 train 状态的差异也需一并验证。

## 3. 已确认的事实：固定分批顺序与参数规模

训练索引被排序，每轮顺序相同，没有 shuffle。6 个固定批次的标签比例不同，例如第四标签在第 2 批约 0.1563，第 4 批约 0.4063。SGD 每轮接收同样的批次序列，可能形成顺序效应，但没有对照证据证明它造成当前差距。本轮不修改抽样顺序。

模型共有 4,608,385 个参数，只有 379 行内层训练数据。外层训练原有 474 行，其中 95 行用于验证；直接使用全部外层训练行与当前安全选模协议不是同一设置。论文仅简述五折，未说明相同的内部验证划分，不能把差距全部归到模型上。

## 4. 已量化但尚未确认的机制线索

第 33 轮保存模型在排除自己的训练邻居后：

| 指标 | 训练集 | 验证集 |
| --- | ---: | ---: |
| LRAP | 0.865531 | 0.859240 |
| Micro-F1 | 0.773684 | 0.722955 |
| Macro-F1 | 0.766249 | 0.707870 |
| 加权 BCE | 0.548228 | 0.656784 |

训练与验证的 LRAP 只差 0.00629，不支持“最佳模型明显欠训练”或“又塌缩成常数”的说法；分类指标和 BCE 则存在泛化差距。后期在线训练损失降到 0.2828，验证 LRAP 从峰值 0.85924 降到第 80 轮的 0.84199，是后期泛化未继续改善的迹象。末轮权重未保存，不能据在线损失给出末轮训练集重放成绩。

第一层更新器收到的平均消息 L2 范数：自身 1.382、其他视图 11.314、KNN 11.174、标签 63.448。标签通道按式 (4) 缺少 1/Q 的字面解释求和，明显更大。但输出幅度不同不等于梯度主导，也不证明损害预测，当前不改成均值。

学习率按 `0.001 * 0.933^(epoch-1)` 衰减，第 33 轮约 0.0001087，第 80 轮约 0.000004175。后期步长很小，但不能因此认定慢衰减必然更好；验证分数早于末轮达到峰值。

训练 KNN 没出现明显的极端集中：两个视图最大被选入邻居库的次数为 30、14，前五个节点占全部邻居位置约 6.0%、3.1%。仅凭这些值没有理由认定 KNN 失效。
